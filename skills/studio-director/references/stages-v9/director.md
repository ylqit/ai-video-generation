# 导演计划

所有新输出 schemaVersion=9、contractRevision=2。先设计镜头的注意力和信息变化，再自动形成 sceneDesigns 与镜头 staging；不要求用户逐一确认坐标。每个剧本场景有一个设计，空间不适用时明确 not_applicable 与理由，镜头 staging=null。简单产品、纯视觉、讲解可使用静止或正面构图，无强制反打或运动配额。

sceneDesigns 是空间的唯一可编辑来源：环境主体、区域、墙门、机位、代理形体、通用交互锚点。坐标 x/y 为平面归一化坐标，heading=0 朝图上方，90 朝右；锚点 position 是目标代理形体内部的局部坐标，normalHeading 是相对目标朝向，height 是局部高度。只有有尺寸依据才声明 measured 和 space。未知位置、朝向、锚点或范围保留 null；示意布局不输出伪精确距离。复用模板固定 source 版本，本次修改不回写模板。

每镜明确 audienceFocus、informationChange、cutReason、visibleSpace、visualTreatment、staging 与 interactions。后三项可执行文字只描述本镜可见世界，不放图片制作步骤、后段安排、额度、审批或测试。staging 引用场景与机位，entry/exit 保存身体朝向和位置；空数组继承已建立状态，显式 null 表示未知。路径与门的变化使用镜内帧，连续镜头入口与前镜出口一致；时间省略应在组的 transition/reason 明确。表演 attention 指向主体/锚点或空间点，headHeading 独立于身体方向；无明确关注时保留 null，不默认注视相机。

interactions 用 actorKey、targetKey、anchorId、eventId 表达操作、接触、交接、支撑与穿越，写出 effector、precondition、action、result。effector 可是工具、爪、机械夹具等，不默认人类手部。重要物理互动 required=true 需要锚点与空间依据。多人互动、共同关注、反打轴线、路径、持物默认准备空间设计；复杂互动提供灰模预演，预演不代替实际审核。

对白 mouth 声明 visible / occluded / out_of_frame / unknown，window 是本镜半开帧区间或 null。画内对白允许侧脸和遮挡，不能为口型核对把人物全部转向镜头。实际嘴部可见区间仍要看片核对；未知不是豁免。

先建立全片时间轴，再安排镜头和制作单元。每镜 frames 为24fps整数帧，但不按镜头数量套秒数。groups.shotIds 给出实际顺序，每镜恰好属于一个组。专业草稿没有 H3 时长上限；当前提供执行能力时尽量在完成节拍处形成可执行组，不能为服从时长而遗漏原文。

镜头包含叙事任务、主体、动作、摄影、表演、声音、事件与对白引用、入口出口状态。动作完成后下一镜从新状态继续，不换景别重演。事件拆镜用 start/continue/complete；同镜完成用 whole。跨独立生成优先在可剪落点处切断；确需接续未完成动作时，明确动作阶段、方向和实际边界来源，生成后联合审看。明确连续、时间省略、换场或历史段及其原因；continuous 的入口状态对齐前出口，不能用计划结果假装真实采用边界。

表演从触发、目标和阻碍推导可见反应。选择当前景别能观察的呼吸、目光、手部、下颌、肩线或动作质感，错峰推进；不同时堆满所有通道。潜台词基于已有关系，通过身体与对白反差表达。机位变化由信息或动作触发，写清发生与停止的理由。

空间重要时写清主体落位、视线目标、接触点和摄影机关系；未知坐标保留未定义，不编造毫米级精度。产品和无人镜头不必填写人物表演。dialogue 中的 lineId 精确引用当前场景台词，最终执行从同一来源取原文，不另写一版对白。

visibleSubjectKeys 只包含本镜可见主体。每句对白声明 delivery=onscreen、offscreen 或 voiceover；onscreen 的说话人必须可见，offscreen 的说话人不得列为本镜可见，voiceover 不要求口型。entryState/exitState 使用 script 声明的属性与取值；未知值用 null，不能把未知当否定。关系仅声明真实使用的对象与附着点，不默认人体部位。

每项 performance 提供稳定 id。关键事件、对白与表演可以用 cues 引用已有对象；window 为镜内24fps半开区间或 null，afterIds 为本镜 cue ID。未明确时点时保留 null，不编造精确帧；不要求所有动作都有 cue。保持有依据的先后与错峰，拒绝循环或窗口越界。时序属于模型文字请求，实际满足程度仍需看审。


## 导演与剪辑方法修订 9.3

按“观众获得什么→景别机位与空间→动作表演声音→参考与切出→生成组”组织设计。事件、镜头、生成片段和采用区间分别承担叙事、观察、执行与实际剪辑职责。动作匹配、视线匹配、反应插镜、道具特写与空镜是呈现方案；切点、淡入淡出和叠化属于后期操作。不要靠叠化掩盖动作缺失，Prompt 时间戳也不保证模型精确切镜。

每次局部修订同时检查左右邻镜：已完成的动作不得无理由重启；允许有明确叙事用途的回放、闪回和时间省略，并标明依据。声音可以先于画面出现或跨镜延续，不让每个片段重新触发全场声音。机位、表演强度与镜头密度都是服务内容的方法，不建立固定数量与固定秒数门槛。
